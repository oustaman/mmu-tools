# ai-samples.json — a capture job with a shelf life

**~20 generated screens, each checked against a declared spec. Empty on purpose.**

## Why this folder is empty

Nothing in it was generated by a pipeline, and nothing in it may be. A drawn
approximation of "what a generator produces" would be a claim about generators
wearing the clothes of evidence about them — the exact failure that put 600
invented records in this estate's rejected pile.

It is also the one dataset in the corpus that **gets worse with age**. A row
here is a fact about one tool on one day, not a fact about generators. The
models change quarterly; a 2026 sample is a 2026 sample and says so.

So: capture it close to the term, with whatever students are actually holding,
and date-stamp every record. Plan to recapture annually and expect to throw the
old rows away rather than average them in.

## The two halves

**Measured, by `pipeline/capture_generated.mjs`.** Grid, palette with every
text-on-background contrast pair, type sizes, target sizes — taken off the
rendered output with no opinion in them. Then compared to `spec.json` and
recorded as `against_spec`: how many pairs fail, how many targets are under
44px, which type sizes are off the declared scale. That comparison is week 6's
lecture as data.

Only `output_kind: "code"` can be measured — a URL or a local HTML file the
generator produced. An `image` row gets marked `measurable: false` and left
there, because you cannot read a type scale off a picture of one.

**Annotated, by a person.** `does_well`, `does_badly`, and whether the output
is competent. Null until filled; a null is a queue, not a gap.

## The shape of a target

```json
{
  "id": "sd-gen-001",
  "prompt_id": "plant-app-home",
  "prompt": "the prompt, verbatim, including any system preamble",
  "tool": "name of the tool",
  "tool_version": "model or build string, if the tool states one",
  "generated_on": "2026-10-07",
  "variant": 1,
  "output_kind": "code",
  "url_or_file": "https://… or file:///…",
  "licence_note": "who owns the output under that tool's terms, and what that permits",
  "operator": "who ran it"
}
```

`variant` is what makes week 6's third item work: run one prompt three times,
keep all three, and the room can show what varies when nothing in the request
did.

## Rules for a sample

1. **One prompt, recorded verbatim.** A paraphrase is not the prompt.
2. **Three variants minimum per prompt**, or the variance claim has no evidence.
3. **Name the tool and its version.** "An AI" is not a source.
4. **Date every row.** Undated, a row is worthless within a year.
5. **Keep the output.** A screenshot of a thing you no longer have is not
   re-measurable, and the whole point is that these get re-measured.
6. **Record the licence position.** Generator terms differ on who owns output
   and what may be republished. This corpus is closed-module teaching use; keep
   it that way unless a row's terms clearly say otherwise.
7. **No row without an operator.** Somebody ran it, and that is part of the
   provenance.

## Running it

```
node pipeline/capture_generated.mjs                # measure everything unmeasured
node pipeline/capture_generated.mjs --remeasure    # re-measure rows already done
node pipeline/capture_generated.mjs --limit 3      # a short pass
```

It merges by id and never rebuilds. That is not a convenience: the annotation
half is somebody's judgement, and a rebuild would erase it. `capture_screens.mjs`
carries the same behaviour for the same reason, after an earlier version of that
script silently replaced 90 measured rows with 71.

## What the room shows when it is filled

`interfaces.institute/collections/generated/` — commissioned and named, with a
page saying why it is empty, in the same way the Flows floor and the Observatory
are named and say why they are shut. It opens when there are rows.
